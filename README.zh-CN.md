# Eagle 视频压缩插件

[English Documentation](README.md)

面向 [Eagle](https://eagle.cool/) 的本地批量视频压缩插件。它会自动导入当前在 Eagle 中选中的视频素材，通过 FFmpeg 完成本地转码，并可在成功后将压缩结果替换回 Eagle 素材。

> 所有视频都在本机处理。插件不会上传视频文件，也不会将视频元数据发送到远程服务。

## 功能

- **批量压缩** Eagle 中选中的视频素材，也支持拖入本地视频文件。
- 默认使用 **H.265 / HEVC**，也可选择 H.264、AV1、VP9 和仅重新封装。
- 三种压缩方式：
  - **画质优先（CRF）**：以稳定的视觉质量为目标。
  - **指定码率**：按已知视频码率控制输出。
  - **目标文件大小**：H.264 / H.265 使用两遍编码，尽量接近目标体积。
- **CRF 体积预估**：基于分层片段的实际试编码，展示预估区间而非误导性的精确数字。
- 支持分辨率、帧率、音轨、编码速度、并发数和 10-bit 片源处理设置。
- 可选备份：默认关闭；必须先指定备份目录，才能启用备份。
- 可选同步回 Eagle：压缩成功后替换原始文件并刷新缩略图。
- 设置持久化、一键重置、跟随 Eagle 主题、多语言界面。
- 内置失败诊断；正常使用时日志入口不会打扰界面。

## 运行要求

- Eagle，且 FFmpeg 依赖可用。
- 如果 Eagle 的依赖模块不可用，插件会回退使用本机安装的 FFmpeg / FFprobe。
- 当前已在 macOS 上完成验证。`manifest` 虽声明跨平台，但 Windows 尚待真实设备主流程验证，因此暂不宣称 Windows 已完整验证。

## 安装

### 安装打包发布版

1. 下载 `.eagleplugin` 安装包。
2. 使用 Eagle 打开该文件，或从 Eagle 的插件面板安装。
3. 若 Eagle 已在运行，请重启 Eagle 以重新加载插件代码。

### 从源码安装（开发用途）

1. 克隆本仓库。
2. 在 Eagle 的插件面板中加载包含 `manifest.json` 的插件目录。
3. 修改源码后重启 Eagle，或从插件面板重新运行插件。

本仓库在 macOS 上的本地开发同步命令为：

```bash
./sync-to-eagle.sh
```

该脚本会先检查 JavaScript 语法，再将插件同步到 Eagle 本地插件目录。它只用于开发，不应被打进正式发布包。

## 使用方式

1. 在 Eagle 中选中一个或多个视频素材。
2. 打开**视频压缩**插件，所选视频会自动导入。
3. 选择编码格式和压缩方式；默认配置为 H.265、CRF 28。
4. 查看原始大小、预估输出大小和空间变化汇总。
5. 如需保留原文件副本，先选择备份目录，再启用备份。
6. 点击**开始压缩**，确认后执行。

### 三种压缩方式

| 方式 | 适用场景 | 体积行为 |
| --- | --- | --- |
| 画质优先（CRF） | 常规压缩、优先保证画质 | 最终体积由画面复杂度决定。插件会对片段试编码并展示预估区间。 |
| 指定码率 | 已知交付码率 | 输出体积按时长、视频码率和音频设置换算。 |
| 目标文件大小 | 有明确体积上限 | H.264 / H.265 使用两遍编码以尽量接近目标；音频与容器开销仍可能带来少量差异。 |

### 空间变化颜色规则

- **绿色**：处理后或预估体积严格小于原始体积。
- **红色**：处理后或预估体积严格大于原始体积。
- **普通文字颜色**：体积几乎不变，或预估区间跨过原始体积、结果仍不确定。

## 安全与隐私

- 视频通过 FFmpeg 在本机处理。
- 插件会读取已选中的源视频，并先将编码结果写入本地临时文件。
- 只有在你发起并确认压缩后，插件才会替换原始 Eagle 素材。
- 备份默认关闭；必须选择备份目录后才能启用。
- 设置和诊断日志仅保存在本机；插件不发起网络请求。

请始终为不可替代的媒体保留独立副本。和所有转码工作流一样，当你选择替换原文件时，这一操作具有破坏性。

## 更新日志

### 1.1.2

**修复**

- **压缩进行中追加素材会先问一次。** 运行期间选「加入任务队列」，新素材会直接被推进正在跑的工作队列，立刻开始编码并覆盖原文件，而弹窗只报了数量和文件名。没开备份时这些原件根本救不回来，界面上却没有任何提示。现在运行中追加会单独弹一个确认框，列出新增文件、写明它们会立即压缩并替换原路径上的文件、并给出本次的实际备份状态 —— 备份未生效时用红字明说「无法恢复」。选「不添加」时正在跑的队列一点不动。
- **安全警告接入语系资源。** 开始压缩前那个确认框里的覆盖、备份和不可恢复警告，全是硬编码的简体中文，英文、日文等界面的用户压根看不到。现在全部走语言包，八个语系都有完整翻译。
- **「同步回 Eagle 素材库」不再被误读成覆盖开关。** 旧文案暗示只有开了这个选项才会替换原素材。它从来就不控制覆盖 —— 无论开关状态，原路径上的文件都会被替换，这个选项只决定要不要通过 Eagle 的替换接口更新关联素材、刷新缩略图。现在勾选框下方补了说明，确认框里明说，八个语系的使用文档都加了独立的「文件替换说明」小节。
- **操作栏按钮不再左右跳。** 汇总数字从「—」变成实际体积时，「开始压缩」和「停止并取消」会从左边弹到右边。操作栏是可换行的 flex，窄窗口下这两个按钮会折到第二行，而负责把它们顶到右侧的占位元素留在第一行 —— 第二行没有东西顶，按钮就贴左。改成按钮自己 `margin-left: auto`，auto 外边距按行生效，落在哪一行都靠右。
- **`hidden` 属性重新生效。** `[hidden]` 的 `display: none` 来自浏览器默认样式表，被样式表里任何一条 `display` 盖掉。`.notice-row` 和 `.sample-analysis-controls` 都写了 `display`，于是 `el.hidden = true` 对它们完全无效 —— 一打开插件就能看到本该藏起来的「分析全部 / 停止分析」。补了一条 `[hidden] { display: none !important }` 兜底。
- **Windows 上「打开日志目录」不再打开错的文件夹。** 回退分支写的是 `spawn('explorer', ['/select,', p])`，`/select,` 和路径成了两个参数，explorer 认不出这是选中指令，会默默打开「文档」，而且退出码正常 —— 界面还会显示「已打开日志目录」。必须拼成一个参数。
- **Windows 上日志与设置不再分家。** 设置文件走 `%APPDATA%`，日志却写死 `AppData\Roaming`。改过 `APPDATA` 的机器上两者会落在不同位置，排查时对不上。日志改成同样优先读 `%APPDATA%`。

**改进**

- **安装包只装运行需要的东西。** 原来的打包走排除列表，而实际打包源是仓库根目录，排除列表从头到尾没参与，于是 `tests/`、`tools/`、`reports/` 和投稿说明一起进了包。现在 `tools/build-package.sh` 用白名单把运行时文件拷进干净的 `dist/<id>/` 再打包，`tools/verify.sh` 会对任何白名单之外的顶层条目报错。没登记的东西进不去。`--zip` 收尾还会自检成品包：zip 完整性、绝对路径与 `..`、`__MACOSX`/`._*`/`.DS_Store`、重复条目、符号链接，任何一条不过就直接失败。
- **写清楚插件在硬盘上留了什么。** 设置和运行日志卸载后都不会被清掉，而用户没有任何途径知道它们在哪儿。现在日志面板顶部同时列出这两个文件的完整路径，八份使用文档也各加了「数据保留与清理」小节，写明 macOS 与 Windows 下的位置、「重置设置」不删文件、以及如何手动清干净。
- **日志面板不再只有中文。** 「已复制到剪贴板」「无法自动打开」这几条提示是硬编码的，切到英文界面照样弹中文。现在全部走语言包。顺带修掉一个提示互相覆盖的问题：提示消失后原来是把「出现前的文本」写回去，1.8 秒内连点两次，写回去的就是上一条提示本身，路径会被提示语永久顶掉。
- **商店文案有了事实来源。** 提交给插件中心的名称和描述只存在于提交表单里，字数超限是被拒稿之后才知道的。现在它们落在 `store/descriptions.json`，`tools/check-store.js` 在提交前就校验各语系的字数上限、名称是否与语言包一致、句子有没有被截断。
- **使用文档写明 FFmpeg 要求。** 八份文档的使用说明开头都加了「使用前准备」，讲清楚 FFmpeg 依赖插件、本机 FFmpeg/ffprobe 回退，以及两者都找不到时插件的表现。

### 1.1.1

**修复**

- **多音轨不再被压没。** 编码流程里一行 `-map` 都没有，完全交给 FFmpeg 的默认流选择，而默认规则是「每种流类型只留一条」。双语音轨、评论轨、5.1 加立体声这类素材压完就只剩一条，而且不报错、不提示，等发现时原文件已经被替换掉了。现在显式指定 `-map 0:v:0 -map 0:a?`，并补上 `-map_metadata 0 -map_chapters 0` 让容器级元数据和章节一起带过去。实测双音轨源：旧命令产出 `[video, audio]`，新命令 `[video, audio, audio]`。
- **压缩后变大不再覆盖原件。** 对已压过的素材二次压缩，或者碰到编码器不擅长的画面，产物可能比原文件还大。旧逻辑照样写回，于是「压缩」反而把文件永久变大。现在提交前先比体积，没变小就不动原文件。
- **取消任务不再留下半截文件。** 取消时直接发 `SIGKILL`，FFmpeg 写到一半被杀会留下截断的目标文件；在「替换原文件」的流程里，这意味着原件没了、新件是坏的。改成先发 `SIGTERM`，等 800ms 让它正常收尾，超时才强制结束。
- **临时文件不再混进素材库。** 为了让最后的提交是一次同卷重命名，中间产物就写在源文件旁边 —— 但那正好在 Eagle 的素材目录里，会被当成新素材索引进去。现在临时文件统一加点号前缀，并用注册表跟踪。

**改进**

- **批量导入不再卡顿。** 以前每探测完一个文件，就把「刷新编码下拉 + 刷新体积预估 + 重画汇总栏」整套跑一遍，而这三者各自都要遍历完整任务列表，于是导入 N 个文件的代价是 N²。现在渲染按内容 diff，批量刷新统一 120ms 节流。以任务数组的读取次数计：100 个文件从 144146 次降到 1000 次（144×），墙钟从 1956ms 降到 345ms。
- **探测素材信息改成 4 路并发。** `ffprobe` 原来是串行的，现在用共享游标开 4 条泳道。25 个真实文件实测：1322ms → 451ms（2.9×），同时在飞的探测数从 1 提到 4。
- **VP9 提速约 2.2 倍。** `-threads` 对 libvpx-vp9 只是建议值，不开 `-row-mt 1` 时它基本单线程跑。补上 `-row-mt 1 -tile-columns 2` 后，1080p 素材从 11.58s 降到 5.32s。CPU 总时间从 41.0s 涨到 46.1s —— 这正是并行化的形状：总工作量略增，等待时间腰斩。
- **提交产物改成重命名而非拷贝。** 旧路径无条件把临时文件拷到目标目录的 staging 再 rename，等于每个任务都多一次全量写盘。现在先尝试直接 rename，只有跨设备（`EXDEV`）才回退拷贝；临时文件本来就在源文件旁边，常见路径下是零拷贝。1GB 文件写回：958ms → 4ms。
- **编码器线程按整机预算分配。** `-threads` 对 libx265 / libsvtav1 无效，所以每个 worker 都按自己的默认吃满 CPU，几个任务一起跑就互相抢。现在改成走这两个编码器真正认的参数 —— `-x265-params pools=N`、`-svtav1-params lp=N` —— 并按编码分别推导上限。8 路并发下 CPU 总时间降 9.4%（H.265）/ 6.4%（AV1）。代价要说清：满载时这不提升吞吐，墙钟反而慢约 5%，因为机器本来就打满了；换来的是余量，不是速度。

**新增**

- **24 核及以上的机器并发可选到 6 或 8。** worker 上限原来是固定的 4，现在大机器上放宽到 8，下拉选项同步扩展。

### 1.1.0

**新增**

- **GPU 硬件编码。** 压缩现在可以走 GPU 而不是 CPU。新增「硬件加速」下拉，三档可选：自动、强制 GPU、仅 CPU。默认「自动」—— 检测到可用硬件编码器就用，没有则静默回退到软件编码，不打扰。支持 NVIDIA NVENC、Intel Quick Sync Video、AMD AMF 三家，启动时查询当前所用 FFmpeg 的编码器与硬件加速列表来探测，并把探测到的硬件名回填到下拉里，这台机器到底能不能受益一眼可见，不用猜。
  - **不是每个格式在每家都有硬件实现。** VP9 没有 NVENC / AMF 实现，Intel 的 `vp9_qsv` 在消费机上又极少可用，所以 VP9 固定走 CPU。没有对应编码器的选项会置灰，而不是选了却被静默忽略。
  - 硬件编码时会主动降低并发。实测 NVENC 并发到 3 路以后吞吐基本不再增长，因此硬件编码的 worker 预算收敛到 2 —— 同时开 8 路只是把同样的总吞吐摊到更多文件上，单个文件并不会更快。
  - **硬件失败不等于任务失败。** 有些驱动会列出自己实际初始化不了的编码器（比如独显被断电的笔记本照样列得出 `h264_nvenc`）。因此硬件编码失败会**自动回退 CPU 重跑一次**，只回退一次，CPU 再失败才算真的失败。
- **画质档位现在能正确换算到硬件编码器。** 软件编码器的 CRF 与硬件编码器的 QP 不是同一个刻度。把 CRF 28 直接当 NVENC 的 `-cq` 用，产物体积会偏离 45% 到 +340%。现在改为换算到 `-rc constqp -qp`：H.264 / HEVC 用 +2 偏移，AV1 乘 3.2（AV1 的 QP 刻度是 0~255，不是 0~51）。

**优化**

- 硬件编码更快，且 CPU 占用大幅下降。1080p30 实测素材上，H.265 从约 28 秒、约 10 核占用，降到约 3 秒、不足 1 核；同等码率下与软编的 PSNR 差距在 0.12 dB 以内。
- 压缩前的体积预估会考虑所选编码器，预览出来的体积反映 GPU 真实会产出的结果，而不是软编的大小。

### 1.0.2

**新增**

- **HDR 识别。** 现在会探测素材是否为 HDR，并在任务列表里用琥珀色角标标出：`HDR10`、`HLG`、`Dolby Vision`、`HDR10+`；当容器只留了 BT.2020 色彩空间加 10bit 位深、没有更多信息时，标注为通用的 `HDR`。判定依据是色彩传输特性（`smpte2084` 对应 PQ/HDR10，`arib-std-b67` 对应 HLG）以及 Dolby Vision / SMPTE 2094-40 的 side data。
  - 额外有一条兜底规则覆盖「容器里根本没有写 `color_transfer`」的 HLG 文件：BT.2020 色彩空间且位深 ≥ 10bit 一律视为 HDR。否则这类文件会被静默漏掉。
- **重编码时保留色彩元数据。** HDR 素材编码时会带上 `-color_trc`、`-color_primaries`、`-colorspace`，让色调映射信息得以保留。少了这一步，HDR10 源压完可能被标成 SDR。
- **「本插件已压缩」标记。** 压缩完成后，会往产物里写入一条机器可读的标记。下次再载入同一个文件时，列表里会显示它已被压缩过，并给出压缩次数和日期 —— 一眼就能看出哪些素材已经经历过一次有损压缩。
  - 标记以 `EagleVideoCompress` metadata 的形式写入。MP4 / MOV / M4V 必须加 `-movflags +use_metadata_tags`，否则 muxer 会**静默丢弃**不认识的 metadata 键：编码正常退出、文件正常播放，标记却没了。MKV / WebM 原生支持，但会把键转成大写，因此读取时做了大小写不敏感匹配。
  - **AVI 和 TS 存不了自定义 metadata。** 因此这两个容器干脆不写标记，并在设置项说明里直接讲清楚，不假装成功。
  - 标记默认开启，可在设置里通过「压缩后写入『已压缩』标记」关闭；关闭后插件完全不碰文件元数据。
- **重复压缩的汇总提示。** 当队列里存在本插件此前压过的文件时，汇总区会提示具体数量，并说明再次压缩会继续损失画质。

**修复**

- **HDR 素材选 H.264 会被静默毁掉。** H.264 预设没有 10bit 通路，用它压 HDR 源会强制转 8bit，HDR 信息不可逆地丢失，且界面上没有任何提示。现在会在汇总区给出黄色警告条。按既定策略只警告、不阻断、不自动改参数 —— 决定权留给你。

### 1.0.1

**修复**

- **H.265 产物在 macOS 无法播放与预览。** FFmpeg 将 HEVC 写入 MP4 / MOV 时默认使用 `hev1` sample entry，把 VPS/SPS/PPS 参数集留在码流里。FFmpeg、Chrome 和 Eagle 会自行去码流中解析，因此能正常播放；但 Apple 的解码栈要求 `hvc1`（参数集写进容器描述信息），否则就表现为「Eagle 里能放，Finder、Quick Look、QuickTime 都打不开」。现在输出为 `.mp4`、`.mov`、`.m4v` 的 HEVC 产物都会带上 `-tag:v hvc1`。
  - 该标签只作用于真正的 HEVC 流。「仅重新封装」模式下目标编码器是 `copy`，看不出真实码流格式，因此必须回看探测到的源编码；给 H.264 流套 `hvc1` 会让 MP4 muxer 在写头时直接失败，整个任务报废。
  - 已经压坏的 `hev1` 文件不需要重编码，无损重新封装即可：
    `ffmpeg -i broken.mp4 -map 0 -c copy -tag:v hvc1 fixed.mp4`
- **替换原文件不再是崩溃安全的。** 之前的做法是把编码产物直接复制覆盖到原路径，中途失败会留下被截断或部分覆盖的原文件。现在改为「在原文件同目录写 staging 文件 → 原子 rename 提交」，取消或 I/O 失败时原文件保持不变。
- **`eagle.item.getSelected()` 同步抛出的异常未被捕获。** 现已包装调用，使同步失败与异步 reject 共用同一条错误处理路径。
- **陈旧的选中素材回调会重新弹出已关闭的对话框。** Eagle 可能在一次打开中连续触发 `onPluginRun` / `onPluginShow`。现在用递增版本号丢弃晚返回的读取结果，用户点过「取消此次操作」后不会再被重新弹窗。

**新增**

- **压缩过程中可见的「停止并取消」入口。** 点击后立即通知 FFmpeg 终止当前编码，把尚未开始的任务标记为已取消，并等待子进程退出、临时文件清理完成后再结束本轮。
- **在 Eagle 中重新选中素材打开插件时的三选项。** 之前的实际体验是：窗口会打开，但新素材无法加入已有任务列表。现在会明确询问：取消此次操作（保留当前队列）、取消当前所有任务并重新添加新选中素材、把新素材加入任务队列。任何情况下都不会静默丢弃进行中的工作。
- **支持向正在运行的队列追加素材。** 压缩过程中追加的新素材会在探测完成后由空闲 worker 在本轮继续处理，无需等到下一轮。
- **采样预估控制。** 批量导入默认只采样少量素材；界面现在显示采样进度，并提供「分析全部」和「停止分析」入口。

**优化**

- 并发数从「进程数量」改为「资源预算」。worker 数由 CPU 核心数、编码器和是否两遍编码推算，并为每个编码器显式设置线程上限，避免多个自带多线程的 FFmpeg 进程互相抢满全部核心。
- 源文件目录可写时，中间产物直接写在该目录下，避免素材存在外置盘或网络盘时额外复制一次大文件；目录不可写时安全回退到系统临时目录。
- FFmpeg 的 `stderr` 只保留末尾 64 KB，不再随长时间多 worker 任务无限增长。
- 进度渲染以 120ms 节流，并复用缓存的任务行节点，不再每个进度事件都重新查询 DOM。
