# Eagle 视频压缩插件

[English Documentation](README.md)

面向 [Eagle](https://eagle.cool/) 的本地批量视频压缩插件。它会自动导入当前在 Eagle 中选中的视频素材，通过 FFmpeg 完成本地转码，并可在成功后将压缩结果替换回 Eagle 素材。

> 所有视频都在本机处理。插件不会上传视频文件，也不会将视频元数据发送到远程服务。

## 功能

- **批量压缩** Eagle 中选中的视频素材，也支持拖入本地视频文件。
- 默认使用 **H.265 / HEVC**，也可选择 H.264、AV1、VP9 和仅重新封装。
- 三种压缩方式：
  - **画质优先（CRF）**：以稳定的视觉质量为目标。
  - **指定码率**：按已知视频码率控制输出。
  - **目标文件大小**：H.264 / H.265 使用两遍编码，尽量接近目标体积。
- **CRF 体积预估**：基于分层片段的实际试编码，展示预估区间而非误导性的精确数字。
- 支持分辨率、帧率、音轨、编码速度、并发数和 10-bit 片源处理设置。
- 可选备份：默认关闭；必须先指定备份目录，才能启用备份。
- 可选同步回 Eagle：压缩成功后替换原始文件并刷新缩略图。
- 设置持久化、一键重置、跟随 Eagle 主题、多语言界面。
- 内置失败诊断；正常使用时日志入口不会打扰界面。

## 运行要求

- Eagle，且 FFmpeg 依赖可用。
- 如果 Eagle 的依赖模块不可用，插件会回退使用本机安装的 FFmpeg / FFprobe。
- 当前已在 macOS 上完成验证。`manifest` 虽声明跨平台，但 Windows 尚待真实设备主流程验证，因此暂不宣称 Windows 已完整验证。

## 安装

### 安装打包发布版

1. 下载 `.eagleplugin` 安装包。
2. 使用 Eagle 打开该文件，或从 Eagle 的插件面板安装。
3. 若 Eagle 已在运行，请重启 Eagle 以重新加载插件代码。

### 从源码安装（开发用途）

1. 克隆本仓库。
2. 在 Eagle 的插件面板中加载包含 `manifest.json` 的插件目录。
3. 修改源码后重启 Eagle，或从插件面板重新运行插件。

本仓库在 macOS 上的本地开发同步命令为：

```bash
./sync-to-eagle.sh
```

该脚本会先检查 JavaScript 语法，再将插件同步到 Eagle 本地插件目录。它只用于开发，不应被打进正式发布包。

## 使用方式

1. 在 Eagle 中选中一个或多个视频素材。
2. 打开**视频压缩**插件，所选视频会自动导入。
3. 选择编码格式和压缩方式；默认配置为 H.265、CRF 28。
4. 查看原始大小、预估输出大小和空间变化汇总。
5. 如需保留原文件副本，先选择备份目录，再启用备份。
6. 点击**开始压缩**，确认后执行。

### 三种压缩方式

| 方式 | 适用场景 | 体积行为 |
| --- | --- | --- |
| 画质优先（CRF） | 常规压缩、优先保证画质 | 最终体积由画面复杂度决定。插件会对片段试编码并展示预估区间。 |
| 指定码率 | 已知交付码率 | 输出体积按时长、视频码率和音频设置换算。 |
| 目标文件大小 | 有明确体积上限 | H.264 / H.265 使用两遍编码以尽量接近目标；音频与容器开销仍可能带来少量差异。 |

### 空间变化颜色规则

- **绿色**：处理后或预估体积严格小于原始体积。
- **红色**：处理后或预估体积严格大于原始体积。
- **普通文字颜色**：体积几乎不变，或预估区间跨过原始体积、结果仍不确定。

## 安全与隐私

- 视频通过 FFmpeg 在本机处理。
- 插件会读取已选中的源视频，并先将编码结果写入本地临时文件。
- 只有在你发起并确认压缩后，插件才会替换原始 Eagle 素材。
- 备份默认关闭；必须选择备份目录后才能启用。
- 设置和诊断日志仅保存在本机；插件不发起网络请求。

请始终为不可替代的媒体保留独立副本。和所有转码工作流一样，当你选择替换原文件时，这一操作具有破坏性。

## 更新日志

### 1.0.1

**修复**

- **H.265 产物在 macOS 无法播放与预览。** FFmpeg 将 HEVC 写入 MP4 / MOV 时默认使用 `hev1` sample entry，把 VPS/SPS/PPS 参数集留在码流里。FFmpeg、Chrome 和 Eagle 会自行去码流中解析，因此能正常播放；但 Apple 的解码栈要求 `hvc1`（参数集写进容器描述信息），否则就表现为「Eagle 里能放，Finder、Quick Look、QuickTime 都打不开」。现在输出为 `.mp4`、`.mov`、`.m4v` 的 HEVC 产物都会带上 `-tag:v hvc1`。
  - 该标签只作用于真正的 HEVC 流。「仅重新封装」模式下目标编码器是 `copy`，看不出真实码流格式，因此必须回看探测到的源编码；给 H.264 流套 `hvc1` 会让 MP4 muxer 在写头时直接失败，整个任务报废。
  - 已经压坏的 `hev1` 文件不需要重编码，无损重新封装即可：
    `ffmpeg -i broken.mp4 -map 0 -c copy -tag:v hvc1 fixed.mp4`
- **替换原文件不再是崩溃安全的。** 之前的做法是把编码产物直接复制覆盖到原路径，中途失败会留下被截断或部分覆盖的原文件。现在改为「在原文件同目录写 staging 文件 → 原子 rename 提交」，取消或 I/O 失败时原文件保持不变。
- **`eagle.item.getSelected()` 同步抛出的异常未被捕获。** 现已包装调用，使同步失败与异步 reject 共用同一条错误处理路径。
- **陈旧的选中素材回调会重新弹出已关闭的对话框。** Eagle 可能在一次打开中连续触发 `onPluginRun` / `onPluginShow`。现在用递增版本号丢弃晚返回的读取结果，用户点过「取消此次操作」后不会再被重新弹窗。

**新增**

- **压缩过程中可见的「停止并取消」入口。** 点击后立即通知 FFmpeg 终止当前编码，把尚未开始的任务标记为已取消，并等待子进程退出、临时文件清理完成后再结束本轮。
- **在 Eagle 中重新选中素材打开插件时的三选项。** 之前的实际体验是：窗口会打开，但新素材无法加入已有任务列表。现在会明确询问：取消此次操作（保留当前队列）、取消当前所有任务并重新添加新选中素材、把新素材加入任务队列。任何情况下都不会静默丢弃进行中的工作。
- **支持向正在运行的队列追加素材。** 压缩过程中追加的新素材会在探测完成后由空闲 worker 在本轮继续处理，无需等到下一轮。
- **采样预估控制。** 批量导入默认只采样少量素材；界面现在显示采样进度，并提供「分析全部」和「停止分析」入口。

**优化**

- 并发数从「进程数量」改为「资源预算」。worker 数由 CPU 核心数、编码器和是否两遍编码推算，并为每个编码器显式设置线程上限，避免多个自带多线程的 FFmpeg 进程互相抢满全部核心。
- 源文件目录可写时，中间产物直接写在该目录下，避免素材存在外置盘或网络盘时额外复制一次大文件；目录不可写时安全回退到系统临时目录。
- FFmpeg 的 `stderr` 只保留末尾 64 KB，不再随长时间多 worker 任务无限增长。
- 进度渲染以 120ms 节流，并复用缓存的任务行节点，不再每个进度事件都重新查询 DOM。
